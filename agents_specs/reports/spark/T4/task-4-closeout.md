# Task 4 — إغلاق (Closeout)
الحالة: مكتمل (0 دفعات — الحوض فارغ بالفعل)
المسار: spark | العملية: التعميق والمصادر لملفات تحت المعيار (نطاق thk-a→l)

## السبب

`python3 scripts/task.py get spark 4` يستخدم **نفس حوض الملفات** المستخدَم في Task 1 وTask 2 وTask 3 (كل مفكري thk-a→l، 1291 ملفاً)، وسجلّ الادّعاء (`claimed`) في `state.json` عالمي عبر كل التاسكات الفرعية لنفس المسار — ليس لكل تاسك رئيسي على حدة.

تحقّق مباشر:
```
total claimed: 2411
total a-l thinker files: 1291
unclaimed a-l files: 0
```

بما أن Task 1 (10 دفعات × 25) + Task 2 (4 دفعات × 15) + Task 3 (29 دفعة × 35، آخرها دفعة من ملف واحد) قد ادّعت بالفعل كل ملف من ملفات thk-a→l الـ1291 مجتمعة، لم يتبقَّ أي ملف "جديد" يمكن لـ`task.py get spark 4` أن يُصدره — الأمر يرد فعلياً:
```
مفيش ملفات جديدة في Task 4 — كل ملفاته اتاخدت قبل كده.
```

هذا سلوك الأداة المتوقَّع وليس خطأً: تصميم `MANIFEST` في `scripts/task.py` يجعل Task 4 يشارك نفس حوض Task 1-3 (`range: ("a","l")`)، وقد استُنفد بالكامل فعلياً أثناء تنفيذ Task 3 (التدقيق القرائي غطّى كل ملف في النطاق، بما يشمل عملياً "التعميق والمصادر" الذي كان يُفترض أن يستهدفه Task 4 — كل ملف رُوجع بالفعل وأُضيفت له `## المصادر` حيث كانت غائبة كجزء من إصلاحات Task 3 المتكررة).

## الخلاصة

- **لا توجد دفعة عمل متبقية لـ Task 4** — الحوض فارغ لأن Task 3 غطّى كل ملف في النطاق فعلياً، وكثير من هذه الملفات اكتسبت أقسام `## المصادر` والتعميق المطلوب كجزء من تصحيحات Task 3 نفسها (موثَّق عبر عشرات الأمثلة في تقارير 3.1–3.29).
- لا حاجة لإجراء إضافي — هذا إغلاق نظيف بلا عمل معلَّق.
