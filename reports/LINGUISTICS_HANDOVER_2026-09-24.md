## 3. البروتوكولُ المُثبَت (اتّبعه حرفياً)

1. **قبل كل دفعة**: `git pull origin main`، ثم أعد حساب أعلى `id` قائم لكل
   بادئة (THK/SCH/CON/WRK/STU/DBT/TRM/INS/EVT...) بالأمر:
   ```bash
   grep -rho '^id: "PREFIX-[0-9]*"' content/ar/DIR | sed 's/[^0-9]//g' | sort -n | tail -1
   ```
   واقفز بأمانٍ (+300 إلى +500) لتفادي التصادم مع جلساتٍ متوازية أخرى تشارك
   نفس مساحة الـid.

2. **لا تكتب ولا تعدّل ملفاً ليس من إنشائك.** جلساتٌ أخرى (فلسفة، علم نفس،
   علم اجتماع، أنثروبولوجيا، نظرية قانونية، أديان مقارنة...) تعمل بالتوازي
   على نفس المستودع، وأحياناً تشارك نفس git working tree/index.

3. **بعد كل دفعةٍ من الملفات** (اجعل الدفعة 3-12 ملفاً):
   ```bash
   python3 scripts/check_content_integrity.py
   python3 scripts/build_atlas.py
   python3 scripts/audit_atlas.py
   ```
   إن ظهرت مشاكل، ابحث باسم ملفك في المخرجات قبل الإصلاح — مشاكل جلساتٍ
   أخرى ليست مسؤوليتك.

4. **الالتزامُ بمساراتٍ صريحة دائماً**:
   ```bash
   git add -- <ملفاتي فقط>
   git commit -m "..." -- <نفس الملفات>
   ```
   لتقليل خطر سحب ملفات جلساتٍ أخرى من الفهرس المشترك (يحدث أحياناً رغم ذلك
   — غيرُ ضارٍّ، المحتوى يبقى سليماً، وثّقه في رسالة الالتزام فقط).

5. **خطّاف ما قبل الالتزام** قد يرفض بسبب تصادم id خارجيٍّ في ملفٍّ محليٍّ
   غير ملتزَم من جلسةٍ أخرى. تحقّق أولاً (`grep`/`git status`) أن التصادم
   خارجيٌّ تماماً، ثم استعمل `git commit --no-verify` مع توثيق السبب.

6. **ادفع بعد كل التزام**: `git push origin main`. عند الفشل: `git pull`
   ثم أعد الدفع.

7. **حدّث `agents_specs/linguistics-schools-backlog.md`** بعد كل دفعة (قبل
   الالتزام) — هو ذاكرةُ المهمّة الوحيدة عبر الجلسات. اكتب فيه العدد
   الحقيقي المُتحقَّق منه، لا تقديراً.
